## 3. 操作與資料契約

### 同步與邊界

QGIS 按鈕同步產生帶 CRS、來源 hash、StudyArea 版本的新快照。平台已有草稿時顯示差異與衝突，不覆蓋。無須關閉 QGIS；無須持續即時串流。平台保存狀態，聊天紀錄和 QGIS 畫面都不能替代正式資料。

StudyArea 是研究範圍。ContextExtent 是外部分析範圍。ExplorationDesignArea 是人類指定的概念設計／指標分母範圍。分區是設計需求圖層。這些概念不能自動等同具法律含義的 DesignBoundary；正式地籍、所有權、分區法規或可建性結論仍需既有批准流程。

保留／移除標記只改 scenario overlay。觀測到的建築、道路原始快照仍保留；「可移除」不是現實拆除許可。未決要素預設不被生成器任意刪除。

### 約束與容積率

AI 把敘述轉為可預覽的設定：作用範圍、單位、硬性上限／必須條件、偏好、來源、缺失資訊。設計者確認後才生效。容積率是不能超過的上限，不是越高越好；整體與分區同時驗證。分區重疊時先解決分配規則，不能重複加總。

概念 FAR = 計入的總樓地板面積／明確的設計面積。保留建築也要計入；缺樓層／用途資料顯示未知或有來源的假設，不填零。機能配置、建蔽率與樓地板計入規則是版本化專案設定，不宣稱為當地法規。3.5 m 僅是訪談舉例，不能寫成已批准層高。

### 多尺度 Space Syntax

核心採用同一張清理後的街道路網，在三個公尺半徑計算 angular integration 與 angular choice。記錄引擎、分段方式、角度成本、度量半徑、是否正規化、公式版本、孤立元件和邊界效應。若採 NAIN／NACH，必須明示並以相同定義校驗。一般 closeness／betweenness 不能冒充 angular syntax。

800 m、2 km、10 km 是初始尺度設定，並非已驗證的步行／自行車／汽車模型。AI 不能把 integration 直接說成人流量、choice 直接說成交通預測。依道路功能區分三種交通模式是可選精細模式；未知 access/tag 保留不確定性。

分析半徑與下載 buffer 分開。5 km buffer 不足以直接支持 10 km 結果；20 km 只是待驗證的擷取候選。須檢驗 study-area 結果在擴大範圍後的穩定性與網路缺失，對邊緣受影響段標記限制。不可沿用 spatial-r01 的狹窄 envelope 就宣稱完整區域分析。

### 生成與編輯

預設產生三個有效且策略不同的方案；資源允許增至五個。各方案共享已批准硬限制，並解釋不同的空間組織。中央開放空間、格網、綠軸等是策略例子，不能違反使用者已選的必要條件來湊多樣性。幾何引擎計算道路階層、街廓、建築、用途與開放空間；AI 提供策略與理由。

先只編輯平台生成的量體，不做外部模型匯入。頂面拖曳每次一層：高度由首層與標準層高構成。取消 Shift 自由垂直拉伸。側面位移以相對原位置的 1 m 為步進；不強迫 GIS 絕對座標、原始面長或吸附位置四捨五入。

分面工具支援在平面上畫線／封閉輪廓、切出面片，再局部推拉；先限定可驗證的平面多邊形與逐層體塊，不承諾任意曲面 CAD。自交、非流形、懸空或無可辨识樓層的結果不接受。分面不重複計算樓板；退台與局部擴張按每層實際 footprint 算面積。

道路吸附包括端點、中點、交點、最近點、垂直點、沿線四分之一與四分之三點；吸附以精確接通為準，優先於步進。吸附容差以地面公尺記錄；上下跨越道路不得因平面交叉而錯接。拖曳後重新驗證拓撲，不能只改渲染線條。

側欄即時顯示樓層、高度、GFA、FAR、建蔽率、整體／分區剩餘額度。拖曳預覽可由前端估算，但必須標示預覽；提交、接受與分析使用後端確定性重算。違規草稿可儲存與 undo/redo，標紅具體原因，不能成為有效方案或送正式環境分析。

### 環境分析依賴

| 層級 | 範圍 | 優先度與入口 |
|---|---|---|
| E1 | 指定位置、時區、日期與時段的日照時數／陰影 | 核心；按方法所需位置時間與幾何驗證，不一律要求 EPW |
| E2 | Ladybug 輻射篩選＋Honeybee-Radiance 驗證 | 核心；正式數值需已批准的天氣方法、材料與感測規則、實驗計畫 |
| E3 | 建築耗能 | 高優先附加；另需用途、時程、內部負荷、圍護與系統假設，不能從輻射推估冒充 |
| E4 | 材料熱容量／蓄熱影響 | 高優先附加；瞬態模型、材料性質與邊界條件明確，不能只看材料顏色 |
| E5 | 建築周邊風場 | 最後附加；CFD 網格、邊界條件與校驗；風玫瑰不等同風場 |

W4 提前評估所有工具路徑，E3/E4/E5 不必等 W8 才知道能否執行。正式比較須保存鎖定控制與變更清單；兩種輻射方法各自比較前後，不直接比較其絕對值。保留失敗與未改善結果。旧單棟單軸實驗保留為回歸案例，不再限制整個產品只能做該操作。

### 出圖

必要基線為可下載 PNG：基地分析／Syntax 地圖、量體平面、透視、等角、環境熱圖、方案對照。提供固定視角、解析度與簡單標題／圖例版型；隱藏操控軸、選取框與聊天。平面圖適用的比例尺與北箭頭、分析單位／時段、方案版本與資料限制不可遺失。透視不能使用誤導的單一平面比例尺。

比較圖使用一致鏡頭與色階，或明示色階不同。過期、未接受或示意結果須可辨認，不能輸出成已驗證成果。模型 OBJ／FBX／DWG 輸出是附加功能，先選一種真正可驗證的格式；不承諾三者全部。沒有外部匯入要求。

## 4. 架構修訂

沿用 FastAPI、Pydantic、SQLite append-only ledger、immutable artifacts 與受限 QGIS facade。新增的前端、分析、生成、編輯與出圖子系統不繞過這些邊界。新檔案與測試的預定位置見兩份執行計畫；列出的新檔案是待建置，不是假稱現有 API。

建議資料流：QGIS sync → ContextSnapshot → FeatureDisposition + SpatialBrief → SiteEvidence → ScenarioDraft → ValidatedScenario → HumanAcceptance → AnalysisRun → FigureArtifact。

上述名稱是新契約規劃。實作前用 typed schemas 綁定現有 StudyArea、Artifact、ParameterDefinition、HumanDecision、Scenario 與 EvidenceResult；不得建立另一套聊天內狀態。每個 job 記錄輸入版本、工具／模型版本、計畫、輸出與狀態；舊 revision 的延遲回應不能覆蓋新結果。

LLM 的新增職責：有來源的基地解釋、設計訴求結構化、參考圖檢索、策略提議、具作用範圍的編輯指令與比較評論。引用失配、憑空數字、隱含整體排名、越界工具指令均拒絕。參考圖片保留 URL／作者／授權資訊，不當成模擬證據。模型供應商沿用 provider-neutral contract，W4 驗證一個實際配置，不能僅靠 deterministic mock 宣稱 AI 接入完成。

## 6. 完成標準與進度表達

「Week 8 至少 90%」是排程目標，不是測得的進度。W4 凍結核心檢核表與附加項目，分別報告已驗收／未驗收項目，不以綠色單元測試數計算產品完成率。Week 8 報告版要求 R26-01–14 的核心路徑全部完成；未完成 E2 或 Syntax 必須如實列為核心缺口，不准改成附加項以湊 90%。

每週 gate：輸入／輸出 hash、收集到的測試 node、實際 runtime 證據、手動操作錄影或圖、ledger 參照、人類決定、限制、獨立覆核者與下一個可執行範圍。狀態為 PASS／FAIL／BLOCKED／OUTCOME_UNKNOWN；附加項可為 NOT_STARTED，不能冒充 PASS。

不相依子系統可平行建置；缺失的 gate 只阻擋真正依賴它的工作。缺天氣不阻擋 UI、生成、Syntax 或無天氣依賴的 E1；缺有效 geometry 阻擋該方案正式模擬。
