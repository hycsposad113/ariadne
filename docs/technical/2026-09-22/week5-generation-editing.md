## 1. 本週真正要交付的體驗

設計者輸入「中央多一點開放空間，沿主要道路安排商業」，檢查 AI 整理的需求，設定整體／分區上限，看到至少三個策略不同的方案。每個方案能說明道路、街廓、機能與量體如何回應基地。選 B 後可以移動／旋轉／推拉建築、調整道路節點，儀表板反映變化；不合格草稿可留存，但不能當作有效方案。

這一週的重點不是跑一個生成器得到任意 mesh，而是串好「需求 → 策略 → 可計算幾何 → 指標 → 人類選擇 → 修改」。

## 2. 入口資料與可繼續的工作

| 輸入 | 必須知道的內容 | 不足時的處理 |
|---|---|---|
| StudyArea／概念設計範圍 | ID、版本、geometry、CRS、確認狀態 | 可做 synthetic fixture；真實場景生成受阻 |
| 保留／可改／未決要素 | 穩定 feature ID、來源 hash、決策版本 | 未決項不被自行刪除 |
| 局部分區與 brief | polygon、hard/soft 類別、機能／開放空間意圖 | 先供預覽，不自動當硬限制 |
| 基地／Syntax 證據 | 方法、尺度、來源、有效版本、限制 | 缺項明示，不虛構指標替生成找理由 |
| FAR／coverage／高度／層高 | 作用範圍、單位、上限、批准來源 | 未選數值保持未設定 |
| 外部道路與連接位置 | 拓撲、可接節點、跨越層次、資料缺口 | 不以視覺接近宣稱可連通 |

天氣未解決不擋本週。grocery 政策尚未批准時，只阻擋相應 accessibility 結果；不必連帶禁止所有幾何功能開發。

## 3. Brief：自然語言如何成為可用設計需求

**已確認：** 整體需求＋可選局部框選；AI 協助理解，使用者仍控制設計。

**建議的需求項欄位：** 原始文字、作用區域、對象、機能／幾何目標、hard/soft、值與單位、來源、確認版本、衝突。這些是欄位需求，不是現有資料庫 schema 宣告。

需要分辨四類語句：

| 語句例子 | 解讀方向 | 不可擅自做的事 |
|---|---|---|
| 「容積率不能超過 X」 | 硬性上限 | 當作一定要做到 X |
| 「希望中央更開放」 | 軟性偏好，待描述可衡量方式 | 自創一個中央綠地比例並說已批准 |
| 「這棟留下」 | 明確対象的保留要求 | 挪動它來改善方案分數 |
| 「這區商業多一些」 | 分區用途偏好 | 假定整區 100% 商業或等同法定用途 |

**衝突處理：** 例如保留建築占用希望成為公園的區域，先顯示兩項需求的空間交集與可選方案。AI 可提議改公園形狀、改偏好、或由人類解除保留；不能默默刪樓或降低需求。

**待決：** 「更多」「中央」「混合」的具體定義。可先用可視化選項協助人類選擇，無需一開始建立龐大自然語言分類器。

## 4. 邊界與分區：必須先分清楚分母

- StudyArea 用來研究與看 context；ContextExtent 可能更大，服務三尺度分析。
- 概念設計範圍用來生成與計算面積；不能直接取整個下載 bbox 當分母。
- 分區可能只是註記區，也可能有自身上限；用途必須明示。
- 法律上的 DesignBoundary 與上述探索性範圍分開，不能因生成有效就宣稱可建。

**建議的跨區處理：** 有樓板跨越兩分區時，以樓板與分區的幾何交集分配面積，而不是只看建築中心點。這是工程建議，正式採用前需要確認計入規則。若分區重疊，先整理為互斥計量區或明確優先規則，不能重複扣額度。

**容易出錯：** 變更設計範圍只更新地圖外框，FAR 仍用舊分母；或讓每個候選自選有利分母。比較方案時分母與計入方法必須一致。

## 5. FAR、建蔽率、保留建築與機能

概念指標採明確版本化定義；下列不是地方建築法規解釋：

```text
GFA = 所有計入樓板 polygon 的面積總和
FAR = GFA / 有效設計面積
coverage = 計入建築 footprint 的 union 面積 / 有效設計面積
分區 FAR = 分配到該區的 GFA / 該區有效面積
```

樓板相互重疊、建築接合與保留／新建重疊要先校驗。coverage 用 union 避免重複加總；但 GFA 要按樓層計入，不能把所有樓層 union 成一層。

保留建築的現有 GFA 會消耗整體／分區額度。缺樓層資料時，提供「觀測缺口」與可追溯假設選項；不得把未知當零，製造虛假的新建容量。

機能應至少能追到 building／floor／zone 的分配關係。地面層商業、上層住宅的混合用途不宜只用整棟單一 label 表示。用途比例要說明用 GFA、地面面積還是棟數作分母；本輪未決定法規級細部用途計算。

**檢核例：** 三層等面積量體加一層後，GFA 增加一層面積而 footprint 不變；只改用途不應改總 GFA；同一 geometry 在不同視角下數值不變。

## 6. 生成系統：先組織道路與開放空間，再配置量體

建議的生成順序為：

1. 鎖定保留物、設計範圍與可接的外部道路。
2. 定義策略骨架：主軸／中心、開放空間、主次道路連接。
3. 形成街廓與可配置區；扣除保留物及明示不可建區域。
4. 配置用途與量體，檢查各區額度、道路服務與入口關係。
5. 確定性計算、保留失敗候選、形成策略說明與比較卡。

這是概念設計生成，不保證完成道路工程、消防／日照法規或真實地籍分割。

| 技術問題 | 必須注意 |
|---|---|
| 中心線與道路面積 | 道路寬度、路口處理、街廓切分會影響建築可用空間；不能只畫線後把整地全蓋滿 |
| 內外連通 | 檢查接到有效外部節點，保留 grade/layer；不跨水、跨橋亂接 |
| 碎片街廓 | 狹長或過小碎片要標出，不可強塞量體；門檻是版本化設定 |
| 用途可達性 | 商業／住宅入口與道路、公共空間的關係需要明示，不能只填顏色 |
| 開放空間 | 幾何上未建築區域不自動等於公共可達綠地 |
| 不可行 brief | 回報哪些限制互相衝突、候選在哪一步失敗；不降限、不假造成功 |

## 7. 三至五個策略如何確實不同

**已確認：** 預設不同空間策略，至少三個有效候選，最多五個目標。

可比較的維度包括主要道路組織、開放空間連續性、街廓尺度、建築朝向與組團、用途分布、內外連接。中央庭院、連續綠軸、開放組團是示例，並非已批准的固定三類。

建議每個策略保存「策略敘述＋幾何特徵＋來源證據＋硬限制一致性」。多樣性檢查可以發現同一模型只改高度的假多方案；正式自動化差異門檻仍待 fixture 驗證，不在本文件捏造數值。

同一策略、seed、輸入與引擎版本應可重現；如使用浮點 geometry，先定義 canonicalization 與容差，不假設任何平台的原始 mesh byte 都天生相同。來源 AI 的文字生成與確定性幾何重播分開保存。

若只能得到兩個有效方案，就呈現兩個及失敗原因，核心 3 方案 gate 尚未通過；不能把不合格方案放進有效比較來湊數。

## 8. 基本編輯：畫面操作要有可重播意義

建議每次操作記錄 target ID、父 revision、命令類型、參數、作用座標系、前後 geometry refs、validator result。滑鼠拖曳與 AI 指令用同一命令入口。

| 操作 | 已確認規則／技術注意 |
|---|---|
| 移動／旋轉 | 不破壞保留鎖定；旋轉 pivot 與角度單位明示，步進尚未由人類指定 |
| 頂面拉高 | 一次一層；使用首層與標準層高，不支援 Shift 自由高度 |
| 側面推拉 | 相對起點每 1 m；不整數化地理座標；建議沿面法向處理，需 prototype 驗證 |
| 縮放 | 先用可理解的側面尺寸操作落實，不悄悄加入會破壞層高的三軸自由縮放 |
| 道路節點 | W5 完成端點／最近點與保留鎖；W6 補齊分面及其他吸附 |
| Undo／Redo | 回復幾何與相關數值、選取關係；不刪已批准或計算出的歷史結果 |

拖曳中的 preview 可以快，提交後必須後端重新驗證。若後端拒絕，要留下清楚的違規草稿與原因，不能讓畫面顯示已成功而資料仍停在舊值。

## 9. 儀表板與效能

最小儀表板包含選取棟的層數／高度／GFA、整體與相關分區 FAR／coverage、上限與剩餘額度，以及數值屬於 preview 或正式確認。

一個拖曳動作不應每個 pointer event 都派送正式模擬。建議前端局部 preview、節流更新、結束後提交；確切回應時間與可承受 building／face 數在 W5 量測後寫成效能預算。本文件不保證「即時」等於某個尚未測量的毫秒值。

前端渲染 mesh 與計量模型要能對回同一物件。GIS 大座標可以轉到局部原點渲染，但存回時須可逆，不讓螢幕精度問題改變基地位置。

## 10. 方案比較與人類決策

比較表必須並列數值、單位、同一分母／方法、資料缺口及驗證狀態。不要把「指標更高」一概叫更好：integration、FAR、日照與輻射都有不同設計語境。

AI 可說「此策略更集中開放空間，但某些入口距離較長」，但後半句需要實際路徑證據。沒有數據時只能標成待驗證設計假說。

接受 B 是針對特定 revision。之後修改 B 形成新 draft，不繼承整份舊接受標記；已接受 B 仍可作為比較基線。拒絕 A/C 的理由保留。

## 11. 技術議題清單

| 議題 | 何時決定 | 需要的證據 |
|---|---|---|
| 設計／分區分母與跨區計入 | W5-A | 圖示＋面積 fixture＋人類數值設定 |
| 量體表示法與 editor geometry kernel | W5 基本編輯前 | 逐層與分面 prototype，不只 library import |
| 道路寬度／層級／外部接點 | 生成前 | 來源、設計假設與連通 fixture |
| 策略差異判定 | W5-B | 三候選可見差異與可重現記錄 |
| AI 參考圖片使用方式 | 案例功能接入前 | 來源、權利限制、與證據明確分開 |
| 編輯效能／undo 範圍 | W5-D | 實測操作、儲存大小、失敗恢复 |

## 12. Phase 檢核與交給 Week 6 的內容

| Checkpoint | 必須看見 | 不算通過的情況 |
|---|---|---|
| CP5-A | brief、分區、保留與上限可重播 | 只有聊天文字或默認未批准上限 |
| CP5-B | 至少三個有效、不同且可重現策略 | 換顏色／改名稱湊三個 |
| CP5-C | 同規則比較＋真實人類選擇 | AI 自封最佳或接受錯 revision |
| CP5-D | 逐層／側面／基本移動操作與儀表板一致 | 只改畫面，不改計量模型 |
| W5-E 技術檢核 | 道路基本吸附＋分面 feasibility | 線條看似接上、graph 實際斷裂 |
| CP-W5 | 完整可操作片段與獨立覆核 | 只有程式測試總數 |

交付：三策略及失敗候選、approved brief refs、選取決定、B 的不可變基線與後續草稿、每層面積／道路拓撲、操作紀錄、待解技術項目。Week 6 需要這些真實結構，不能只拿 PNG 或一個無語義 mesh 開始正式模擬。
