## 1. 使用者可見成果與相依性

使用者能在量體面上画線／輪廓、分面並局部推拉；道路可以精確吸附；修改後知道哪些分析過期。接著比較日照／陰影與輻射的修改前後結果。

完整編輯不依賴 weather。E1 若採幾何日照方法，需要正確 geometry、地理位置與時間設定；E2 的天氣、模擬方法、sensor 與正式實驗批准缺一不可。W6 開始真實環境串接，W7 完成 E2 核心驗收；不能因 deadline 改寫未解決的 EPW 語義。

## 2. 幾何表示法：不能只有畫面好看

建議分開三種表達但保持一對一 lineage：

| 表達 | 用途 | 必要關係 |
|---|---|---|
| 設計語義模型 | 建築、樓層、用途、保留、分區 | 是 GFA／約束的計量基礎 |
| 拓撲／分析模型 | 有效面、solid、sensor host、遮蔽物 | 從指定設計 revision 轉換並校驗 |
| 渲染 mesh | 即時選取、顏色、preview | 任何選取面可對回設計對象與 revision |

本週先把平面多邊形與逐層體塊做好，不追求任意曲面 CAD。這是可驗證的工程範圍，不刪除使用者已要求的分面功能。

**常見失敗：** 模型肉眼封閉但邊不共享；normal 反向；同位置重複面；布林後產生極細碎片；只修改 render mesh 而 GFA／sensor 仍來自舊幾何。

## 3. 分面與局部推拉的操作細節

1. 選定面及其父幾何版本，進入該面的局部 2D 座標。
2. 畫切線或封閉輪廓；明確處理與面邊界相交、洞口、重複點與自交。
3. 分割後保留舊面到新面片的關係；只分割不推拉時，體積與 GFA 不應改變。
4. 局部水平推拉按 1 m 相對步進；頂部操作遵守逐層規則，不恢復自由垂直拉伸。
5. 重新建立受影響 solid／樓板／用途關係，驗證後才提交。

**需要 prototype 決定：** 在立面畫任意高度的輪廓後如何對應既有樓層。建議將涉及新增可用樓板的操作綁定樓層邊界，或把純立面造型明確分開；不能憑任意 mesh 體積推算半層 GFA。這不是偷偷增加自由拉高功能。

局部擴張不得穿透保留建築或越出硬邊界；局部縮小可能使某層消失或分成兩片，必須有可理解的結果。不能把幾何引擎自動修復後大幅改形的輸出無聲接受。

**檢核例：** 把一片牆分成兩片但不移動，面積帳本不變；上兩層退台只改那兩層 footprint，不改整棟其他樓層；撤銷後回到原幾何與 GFA。

## 4. 樓層、計量与限制

對 N≥1 的一般等層高規則：總高度＝首層高度＋(N−1)×標準層高。複雜退台按每層 footprint 計算 GFA，不使用外框面積×N。

這是概念模型規則，尚不含屋頂設備、地下層、挑空與地方計容法規。若要加入，要另行定義，不用隱藏例外修補數字。

設定變更與 geometry edit 不同：改「標準層高」可能影響多棟，UI 先顯示受影響清單與高度變化；不能讓一棟編輯偷偷改整個專案規則。

相同上限校驗同時用於手動與 AI 編輯。可保存 invalid draft，但 draft 不可直接送正式環境實驗。若只是需要工程測試，以明示 synthetic fixture 執行，與正式結果分開。

## 5. 道路吸附：幾何接上還不夠

| 吸附類型 | 技術注意 |
|---|---|
| 端點／中點 | 中點指整條対象曲線或所選 segment，必須在 UI 明示 |
| 四分之一／四分之三 | 沿選定道路長度計，不是圓的 quadrant，也不直接插值錯誤 vertex index |
| 最近點 | 按地面度量與可連接対象搜尋，不能只用畫面像素距離 |
| 垂直點 | 投影到有效 segment；延長線上的足點若不支援要明示 |
| 交點 | 區分同層平交與橋／隧道；同平面位置不必然存在 graph node |

吸附容差以公尺記錄，螢幕提示隨 zoom 可讀，但不可因 zoom 改變實際拓撲規則。選中候選要標示吸附種類；可取消此次吸附，避免小拖曳跳到遠點。

接到 edge 中段時要 split edge、更新 node/edge IDs、成本與來源 lineage；只把新端點放上去仍可能是斷圖。移動既有節點也要更新所有 incident edges。

**接受檢查：** 無零長邊／未允許重複邊、連通元件合理、最短路徑與成本同步、保留路不被移動；必要的 dead-end 可以保留但應可解釋，不能一概自動刪除。

## 6. 座標與模擬轉換

至少記錄 world CRS、水平與垂直單位、局部原點、旋轉矩陣、真北角與逆轉換。平台渲染 local origin 不可改寫來源的地理定位；模擬結果要能回到正確的地圖／建築面。

**容易出錯：** 公尺被當毫米；模型北向轉兩次；Z=0 當真實海拔；sensor grid 用上一版 local origin；把南北反向的漂亮熱圖当正確結果。

用非對稱 reference geometry 檢查方向與座標往返，避免對稱方盒掩蓋鏡像／旋轉錯誤。高度缺乏垂直基準時記錄限制，不能補造地形高程。

## 7. 分析更新：preview、stale 與正式 job

幾何變更後先標明受影響結果 stale。高度變更會影響遮蔽與環境結果，但在道路／入口／目的地不變時，不該改路網 accessibility。道路變更則重建 graph 及相依的 Syntax／路徑結果。

每次分析要鎖定 geometry、方法與設定。拖曳中不自動發送完整 Radiance 任務；放開後先完成 validator，再由已批准的 rerun 規則或使用者操作啟動。

取消或斷線不等於外部程序必然停止；先查 run receipts／輸出／程序狀態，再決定是否補跑。舊 job 成功也只歸屬其原 revision，不能蓋掉新方案顏色。

## 8. E1：日照時數與陰影

日照時數是指定時間樣本中太陽可見時間的累計，不是室內照度、全天候日光或熱舒適。Ladybug 的官方 Direct Sun Hours 文件以 sun vectors 與 timestep 解釋輸入及輸出；它是 Grasshopper/CAD 元件說明，不能當成平台已具備無 Rhino 的執行路徑證明。[官方方法文件](https://docs.ladybug.tools/ladybug-primer/components/3_analyzegeometry/direct_sun_hours)

**本專案需要固定：** 地理位置、日期／時段、時區與時間標記、太陽位置方法、timestep、context geometry、是否自遮蔽、測試點／面與法向、surface offset、結果單位。

**工程重點：**

- UI 顯示的當地時間與方法使用時間要能對應，DST 不可默默多算／少算一小時。
- 樣本間隔改變時，結果按時間長度累計，不把每條射線都當一小時。
- 感測點不要落在幾何內或因浮點誤差被自己的面完全遮住；offset 與排除規則保存。
- 畫面即時陰影可當預覽，但若只是渲染器光源效果，不標成經驗證的日照計算。

**檢核：** 無遮擋平面、已知遮擋物、夜間、不同比例模型與時間步長；結果不得超過所選有效時段，缺失結果不得填零。

## 9. E2：輻射雙層方法與單位

Ladybug RadiationStudy 區分累積 radiation（kWh/m²）與 irradiance（W/m²）。其文件明示該類別不計完整太陽能多次反射，地面反射用近似處理；因此不能假設篩選與另一 Radiance recipe 的物理設定完全相同。[官方 API](https://www.ladybug.tools/ladybug-radiance/docs/ladybug_radiance.study.radiation.html)

**方法契約：** 兩層分別保存 sky／weather、direct/diffuse 處理、地面／材料、反射設定、幾何、sensor 與 recipe。共享控制與方法固有限制分開寫；對未被某方法使用的材料參數標示不適用，不能假裝已計入。

**本專案比較建議：** 先在各自方法內比较 baseline→modified，再檢查改善方向是否一致；若不同，分析 sensor、反射、幾何或時間設定，而不是任選較漂亮的數值。

對面感測且每面可代表有效面積時，面積加權平均累積輻射＝Σ(Aᵢ×Hᵢ)/ΣAᵢ；Hᵢ 為累積面密度。簡單平均只在相同代表面積條件下才等價。總入射能量與每平方米指標分開；面積改變時，兩者可能方向不同。

這些是分析設計原則，不是本基地的測量。公式分母需說明只包含哪些面；無效或缺失 sensor 要列覆蓋率，不能悄悄排掉後聲稱完整。

## 10. Sensor 與比較範圍是關鍵技術議題

| 項目 | 要處理的問題 |
|---|---|
| 地面公共空間 | 固定世界座標的比較 grid；被新建築占用的點如何標記，要在實驗前定義 |
| 建築表面 | 修改後面可能分裂／消失，不能用相同 list index 假裝同一面 |
| 排除區 | 建築內部、非研究面、保留物等的 exclusion mask 要有幾何依據 |
| 網格解析度 | 先粗後細可做 feasibility，但正式比較雙方解析度與代表面積要相容 |
| 收斂／精度 | 小範例檢查網格與 recipe 變更是否影響結論，容許差異先規定 |
| 比較圖 | 相同色階與明示時段；不能各自 normalize 後以顏色比較改善 |

不同 surface domains 不強迫逐點差分，可改為相同研究區／同類面的面積統計，並說明 domain 變化。更改比較域本身是實驗設計決策，不只是繪圖選項。

## 11. 真實工具接入與待決項

W4 的 import/smoke 只是開始；W6 要證明選定的 headless 路徑能接受平台幾何、產出原始結果、解析單位、回到畫面並保存 manifest。不要引入未批准的 Rhino connector 來掩蓋缺口。

待決項包括 geometry kernel／分面支援邊界、sensor 規則、recipe 選擇、時間與 weather 語義、誤差容許值、運算量預算。這些應由小型可核對案例產生具體選項，不是任選默认值。
