**日期／版本：** 2026-09-22／v1。**對應：** W9-A–D、CP-W9。**原則：** 先確保報告與核心穩定，再按成熟度加值；不改寫 Week 8 的凍結成果。

## 1. 本週的工作排序

1. 解決影響正確性、重現或報告的核心缺陷。
2. 完成正式圖、展示、來源與限制文件。
3. 核心穩定且仍有時間時，優先建築耗能與材料蓄熱。
4. 已有可行性證據才加入精細交通模式／模型匯出；風場按難度最後處理。

這不是說附加項一定全部能在一週完成。W4 應已做可行性檢核，W7 可在不影響核心時開支線；W9 的任務是收尾成熟功能，避免此時才從零整合一套 CFD。

## 2. 保護 Week 8 版本與修復方式

保留 Week 8 的程式／依賴／資料／結果／圖片／報告 manifest。修復產生新版本與差異記錄，指出受影響指標、結果與圖，不覆寫原始成果。

若只是修字型或圖例位置，保留原計算值；若改面積算法、來源解析或模擬設定，就需要重算相依結果並重新驗收。不能用「只是小修」跳過語義差異。

沒有 Git 也要有可回復的版本與檔案清單。新附加功能採獨立設定／資料版本，不能把共享依賴升級後導致舊版無法重跑。

## 3. E3 建築耗能：先定義要回答的問題

**使用者優先度：** 很重要，但排在前段必要環境分析之後。

先選一個清楚的問題，例如在已批准用途與使用條件下，比較 baseline 與變體的冷／熱需求；不一開始宣稱全基地實際營運能源或全年帳單。

Honeybee 官方說明區分 Radiance 日光路徑與 OpenStudio／EnergyPlus 能源路徑；前段輻射功能通過不代表能源工具鏈已通過。[Honeybee 官方說明](https://www.ladybug.tools/honeybee.html)

**主要技術輸入：**

| 類別 | 需要明確的內容 | 缺失時不能做的推論 |
|---|---|---|
| 熱區幾何 | 房間／熱區、邊界面、相鄰關係、窗／遮陽、地面／外界邊界 | 不能把任意 massing mesh 直接當可靠熱模型 |
| 使用條件 | 機能、occupancy、設備、照明、使用時程、設定溫度 | 不能只靠住宅／商業顏色推耗能 |
| 圍護結構 | 材料層、厚度、導熱、玻璃／太陽性質 | 不能用渲染貼圖當熱性質 |
| 通風／滲風 | 室外空氣、開窗、滲風與控制假設 | 不能忽略後把差異全歸因形態 |
| 空調與系統 | ideal load 或具體 HVAC、效率／控制、輸出定義 | 冷熱負荷不直接等於電力消耗 |
| 天氣與時間 | 已批准來源、時區、時程對齊、期間 | 未批准天氣仍阻擋正式結果 |

Honeybee `RoomEnergyProperties` 將 program type、construction set、HVAC 等分开；program type 用来配置 schedules／loads。這提供接線參考，不表示套用 library default 就已符合本專案。[官方 API](https://www.ladybug.tools/honeybee-energy/docs/honeybee_energy.properties.room.html)

**輸出需分清：** 冷／熱需求、設備／照明、系統用能、峰值與累積量；EUI 的分母、期間、單位需一致。只有某栋或某區的結果不外推成整基地總耗能。

**最小可信檢核：** 一個可核對 thermal-zone 模型、有效面相鄰、已知使用時程、無嚴重 geometry／simulation error、输入变化的方向檢查、原始輸出可解析。之後才接平台方案。

## 4. E4 材料熱容量與蓄熱：和材料表面顏色分開

**使用者優先度：** 重要的後續功能，不能因做了輻射圖就宣稱已完成。

首先分辨「材料熱容量」「熱傳導／隔熱」「表面吸收率」與「實際在一天內吸放熱」；它們不是同一數值。Honeybee 的不透明材料模型提供厚度、導熱、密度、比熱與面熱容量等資料項。[材料 API](https://www.ladybug.tools/honeybee-energy/docs/honeybee_energy.material.opaque.html)

**簡化物理概念：** 對均質材料層，單位面積熱容量可由密度×比熱×厚度得到，單位為 J/(m²·K)。這只是材料性質，不代表室外人體更舒適，也不能直接乘全年輻射就得到節能量。

**有意義的比較需保存：**

- 具體材料層與性質來源；替換一層或整個構造的界線。
- 幾何與使用條件、室內／室外邊界、初始條件、時間步長。
- 研究目標：表面溫度、熱通量、峰值延後或負荷變化，選清楚再跑。
- 是否同時改導熱、厚度、吸收率；若全改了，不能把效果只歸因於熱容量。
- 暖機／初期暫態如何處理，以及有無相變等模型適用限制。

建議先用受控單構造／單熱區基準案例，再接單棟；不要從概念材料名稱「混凝土」「木頭」直接生成權威全基地蓄熱熱圖。

**檢核：** 數值／單位與能量帳本合理；更換材料後輸入確實改變；保存不符合直覺與未改善結果。只顯示材料資料卡時，標為材料屬性功能，不能稱動態蓄熱模擬完成。

## 5. E5 風場：最難功能的明確界線

Butterfly 官方路徑將 geometry 接到 OpenFOAM 等氣流分析流程；這是可研究的整合方向，並不代表本機平台已能執行。[Butterfly 官方說明](https://www.ladybug.tools/butterfly.html)

**先區分：** 風玫瑰是來源天氣的方向／頻率統計；都市量體周邊速度分布需要另外的流場模型；行人風舒適／安全還需要合適標準、機率與情境。三者不得換名冒充。

CFD 技術議題包括 domain 大小、入口風剖面、地表粗糙度、風向、邊界條件、turbulence model、mesh 品質與局部加密、收斂、質量平衡、計算高度、結果採樣與網格敏感性。

不在本文件指定任意入口風速、網格尺寸或 residual 門檻。先選有依據的 benchmark，證明方法／環境可跑且結果可核對，再提交具體研究設定。

**附加 gate：** 通過 runtime／benchmark／domain 與 mesh 檢查，才可做一個明確方向的有限實驗；尚未涵蓋多風向與頻率時，不能稱全年行人風舒適。若時間不足，保留 feasibility 結果，Week 8 核心版本不因此退化。

## 6. 精細交通模式：從共同路網到明確政策

前段三尺度 Syntax 用同一路網。精細模式需要分别定義步行／自行車／車行路網與 access、direction、speed/cost、跨越規則、未知標籤政策；不是改三個半徑名稱。

**需要處理：** 單行與自行車例外、步行禁行、私人／條件 access、橋隧與坡道、missing tags、方向圖是否被所選 Syntax 引擎支援。引擎不支援的假設要明示，不悄悄無向化。

簡化與精細結果要各自保存 network hash、policy、coverage 與排除清單，不能把細網分數直接與粗網當相同母體比較。AI 可解釋差異與資料敏感性，不能把過濾後分數直接說成實際流量。

**檢核：** 已知通行規則的小網路、unknown policy 變體、各模式連通性與同一尺度下的可比較範圍。若 access 資料不足，不用臆測補齊，只顯示限制或先不啟用該模式。

## 7. 模型匯出：先選一種真正可用的格式

使用者接受 OBJ／FBX／DWG 其中可行者；格式尚未選定。先以目標接收軟體、需要 geometry 還是 layers/semantics、授權與可用 exporter 評估，不因副檔名看起來熟悉就承諾。

| 匯出問題 | 必須保存／檢查 |
|---|---|
| 單位／座標 | meters、local origin、北向／軸方向、回到地圖的方法 |
| 幾何 | 面法向、封閉／開放要求、triangulation、洞口、保留／新建群組 |
| 語義損失 | ID、樓層、用途、材料是否保留；不能假裝 mesh 檔等同完整研究資料 |
| 外部依賴 | exporter/runtime 版本、授權、接收端可開啟 |
| 可追溯性 | 對應 scenario revision、export settings、檔案 hash |

檢核在独立 viewer／目標軟體開啟，量測一個已知尺寸、看北向與比例、確認 geometry 沒鏡像或消失。不能用「檔案大小非零」作成功條件，也不能把其他格式改副檔名成 DWG。

這不新增外部模型匯入功能。若為驗收匯出而用別的 viewer 開檔，那是驗證輸出，不是平台承諾支援 import workflow。

## 8. 附加功能的四級狀態

| 狀態描述 | 可對外怎麼說 |
|---|---|
| 未開始 | 已規劃，未實作 |
| 可行性完成 | 指定工具／benchmark 可跑，尚未接到正式案例 |
| 原型串接 | 可以接平台資料，但完整方法／驗收尚未通過 |
| 已驗收 | 有輸入假設、實際結果、限制與獨立檢核 |

這是報告分類，不要求覆寫現有模型 enum。不能只因 UI 有按鈕，就從「未開始」跳成「已驗收」。

## 9. 最終封存與未完成工作的可接續性

最終包包含核心 baseline、修復版本、附加版本、報告圖／影、方法／資料來源、驗收與限制。明確提供開啟順序與正確 demo revision，避免評閱者誤開一個後來失敗的實驗草稿。

未完成項至少記錄：研究問題、已驗證範圍、剩餘依賴、失敗原因、可重現的最小案例與下一個具體檢核。不要只留「未來加入風場」一句。
